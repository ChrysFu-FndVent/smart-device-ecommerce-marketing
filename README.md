<p align="center"><code>品类配置 + 多来源文本</code> → <code>数据观察</code> → <code>营销假设</code> → <code>可追溯物料</code></p>

> 将评论、测评、问答和产品页等多来源文本转化为可追溯的数据观察、营销假设、卖点架构与 AI 概念物料；智能手环是本框架的完整验证案例。

| 解决的问题 | 适用场景 | 输入 | 输出 |
|---|---|---|---|
| 商品文本来源混杂、品类术语不同，洞察容易脱离数据，AI 物料又可能虚构卖点或规格 | 智能穿戴、智能家居、消费电子、家电、美妆个护、家居日用、户外、宠物等电商品类的早期研究与营销验证 | 品类配置、公开文本、来源标签、正式规格、风险规则、目标渠道与物料要求 | 描述统计、主题网络、用户与卖点假设、营销架构、元素溯源表、文案或概念视觉 |

## 何时使用

适合利用公开文本完成需求观察、竞品话题梳理、卖点排序、内容方向和概念物料验证。迁移到新品类时，必须先重建品类词典、分析维度、规格事实源与风险规则，不能直接沿用智能手环案例中的 14 维标签或健康类话术。

不适合把混合来源样本直接当作市场总体，也不适合在缺少专业审核时生成医疗、金融、安全性能等高风险主张。

> [!TIP]
> 通用的是输入输出契约和验证方法，不是智能手环案例中的词典与结论。新品类必须先完成小样本试标和人工校准。

## 快速启动

```yaml
category: 扫地机器人
business_question: 哪些问题应进入详情页首屏与负面风险检查
sources: [公开评论, 商品问答, 测评, 产品页]
analysis_dimensions: [清洁力, 避障, 噪音, 维护, 连接, 售后]
spec_source: [正式规格表, 说明书, 检测或授权资料]
risk_rules: [性能条件, 认证表述, 禁止虚构配件与功能]
target_channel: 电商详情页
required_output: [数据观察, 待验证假设, 卖点层级, 元素溯源表]
```

该模板只定义任务接口；维度、阈值和最低样本门槛需在当前品类中重新验证。

## 品类配置

运行前先填写一份 `category_config`，将通用流程实例化为当前商品任务：

| 配置项 | 作用 | 智能手环案例 | 其他品类示例 |
|---|---|---|---|
| `category_terms` | 识别品类名称、同义词和型号 | 手环、手表、健康监测设备 | 扫地机、洗地机；精华、面霜；帐篷、睡袋 |
| `analysis_dimensions` | 定义需要统计的属性维度 | 健康、安全、佩戴、续航等 14 维 | 清洁力、避障、噪音；肤感、成分、包装；重量、防水、搭建 |
| `spec_source` | 约束具体参数的事实来源 | 正式产品资料与检测依据 | 商品规格表、说明书、质检报告、授权素材 |
| `risk_rules` | 定义禁用词、资质与声明要求 | 医疗健康表述与设备资质 | 功效宣称、儿童安全、食品营养、环保认证 |
| `target_channel` | 决定内容结构和规格 | 详情页、海报、短视频 | 搜索广告、直播脚本、社媒图文、门店物料 |

## 使用路径

```mermaid
flowchart LR
    A[配置品类、规格源与风险规则] --> B[采集公开文本并保留来源]
    B --> C[清洗、动态维度标注与主题分析]
    C --> D[分离数据观察与待验证假设]
    D --> E[设计用户、卖点、内容与渠道策略]
    E --> F[生成文案或概念视觉]
    F --> G[数据、规格、合规与版权复核]
```

最短使用顺序：

1. 用 [skills.md](./skills.md) 的品类配置接口定义术语、维度、规格源和风险规则。
2. 按 [workflows.md](./workflows.md) 完成采集、清洗、分析、洞察、策略和物料六段流程。
3. 使用 [prompt-engineering.md](./prompt-engineering.md) 的通用模板生成代码、候选解释、受控文案和图片提示词。
4. 将结论回查到统计输出，再用 [product-design.md](./product-design.md) 形成用户、卖点和营销模块。
5. [data-analysis.md](./data-analysis.md) 展示如何把通用分析模板实例化为智能手环案例。

## AI 与人工责任

| 环节 | AI 可承担 | 人工必须负责 |
|---|---|---|
| 配置 | 提取候选术语、属性和风险词 | 确定品类边界、维度定义、规格事实源和审核人 |
| 采集与分析 | 辅助生成采集、清洗、统计和可视化代码 | 来源授权、抽样策略、指标口径、运行验收 |
| 洞察 | 提供带数字引用的候选解释 | 回查结果，区分观察、假设和业务判断 |
| 营销方案 | 生成结构化初稿与文案候选 | 卖点优先级、用户关系、渠道策略和风险红线 |
| 视觉物料 | 生成概念稿和版式候选 | 规格、资质、品牌、版权、可访问性与发布审批 |

## 验收要点

- `category_config` 中的术语、维度和风险规则经过品类负责人确认。
- 每个策略结论附统计依据，或明确标为待验证假设。
- 所有数字、型号、材质、尺寸、性能、功效等具体主张回到正式规格源核验。
- 低样本品牌或单品只作为风险信号，不作总体口碑判断。
- 来源授权、隐私、版权、广告规范和品类专项要求在发布前人工复核。

## 边界

- 通用的是任务接口与验证方法，不是智能手环案例中的词典、标签和结论。
- 公开晒物、榜单、测评、问答和产品页面组成的混合样本不是严格随机评论。
- 不同品类需重新验证情感模型、词典、维度和阈值；中文通用模型不能自动保证垂直领域准确率。
- 案例海报不对应具体在售产品，图中规格文字仅作概念占位。
